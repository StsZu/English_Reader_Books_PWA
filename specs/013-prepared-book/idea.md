# Підготовлена книжка: текст, переклад, MP3 і час речень

**Стан:** записано 2026-11-10, уточнено того ж дня за рецензією `TASK/2026-11-10_audit_review_and_answers.md` (розділи 2, 4, 5); M1–M9 погоджено 2026-11-10 («ok 013»); D0 виконано в гілці `013-d0-prototype` і виміряно 2026-11-10: підсвічування вчасне (див. «Стан виконання»); D1 виконано 2026-11-10 у тій самій гілці й перевірено на iPad. Основний сценарій — English Reader; перенесення в Polish Reader — окремим запитом після прототипу.

## Формулювання

| | |
|---|---|
| **Проблема** | Текст, переклад і аудіокнига живуть окремо. Під час прослуховування текст не знає, яке речення звучить. Перенести підготовлену книжку разом із перекладом і записом не можна. |
| **Для кого** | Читач, який слухає аудіокнигу й одночасно читає оригінал із перекладом. |
| **Бажана зміна** | Один імпорт дає книжку з готовим українським перекладом, аудіо та часом речень. Під час відтворення підсвічується речення, яке звучить. |
| **Користь** | Читання й слухання стають одним заняттям. Підготовлена книжка працює офлайн без запитів до ШІ. |

Головна цінність — надійний зв'язок «та сама редакція тексту ↔ переклад ↔ той самий запис ↔ час речення», а не нове розширення файла.

## Що є зараз

- Імпорт: EPUB, TXT, MD (`src/core/import/importer.ts`), ліміт 50 МБ (`:8`). Текст розбивається на речення під час імпорту (`src/core/model/segmenter.ts`).
- Модель: `Book → chapters → paragraphs → sentences: string[]`, адреса речення — індекси (`src/core/model/book.ts`, `SentenceRef`, `paragraphKey = "розділ-абзац"`). Стабільних id речень немає.
- Переклад: кеш `translations`, ключ `${bookID}|розділ-абзац`, значення — масив перекладів речень абзацу (`src/core/ai/translation.ts:63-85`).
- Аудіо: окрема база `english-reader-audio` версії 1, сховища `tracks`, `files`, `positions` (`src/core/audiobook/store.ts`). Доріжки можна переставляти й видаляти (`src/core/audiobook/player.ts:259-290`), тому індекс доріжки не є стабільним посиланням. Плеєр знає доріжку й час, але не має карти «час → речення».
- Відступ після паузи: 0,2 с після короткої паузи, 3 с після паузи від 5 хв або повторного відкриття, точно в місце — після явного перемотування (`player.ts:29-36`).
- ZIP-читач тримає весь архів у пам'яті (`src/core/import/zip.ts:24-30`), межа розпакованого — 200 МБ.
- Резервна копія 006: gzip-файл JSON-рядків з книжками й перекладами, без аудіо (`src/core/storage/backup.ts`, `BACKUP_FORMAT = 'reader-backup'`). `restoreBackup` очищує всі основні сховища й замінює налаштування, тому для додавання однієї книжки не годиться.
- Media Overlays (SMIL) і формат 2Books не підтримуються; сумісність не перевірялася.

## Поведінка читалки

- Джерело часу — `audio.currentTime`, не окремий таймер.
- Підсвічується речення, чий інтервал містить поточний час (через наявний механізм активного речення). У паузах між реченнями, на вступі й музиці нове речення не підсвічується.
- Пауза, перемотування, зміна швидкості, перехід доріжки й відступи після паузи (003: 0,2 с після короткої, 3 с після паузи від 5 хв або повторного відкриття, точне місце після перемотування) одразу оновлюють підсвічування.
- **Переклад за аудіо (D3a, погоджено 2026-11-10, «ok переклад»).** Без дотику панель перекладу показує переклад речення, що звучить, і змінюється разом із підсвічуванням. Речення, вибране дотиком, лишається в панелі, доки в аудіо не почнеться наступне речення; після цього панель знову йде за аудіо. На паузі й у паузі між реченнями лишається переклад останнього почутого речення. Якщо переклад вимкнено або виділено фрагмент, нічого не змінюється. Стосується лише аудіо підготовленої книжки. Читання голосом, як і раніше, перекладу за реченням не показує.
- Окремим погодженням: автопрокручування з паузою, поки користувач гортає; «повторити речення із запису»; спільне місце тексту й аудіо.

## Виготовлення пакета (поза PWA)

Читалка лише споживає пакет. Виготовлення — локальний інструмент:

- Текст і аудіо: наприклад, Project Gutenberg + LibriVox. Права перевіряються для конкретного тексту, запису й перекладу. Сторонні книжки й записи в репозиторій не комітяться (конституція, розділ II; C8); у тестах — лише синтетичні фікстури.
- Розбиття: той самий `segmenter.ts` через Node (як `npm run golden`). Версії ICU / `Intl.Segmenter` можуть відрізнятися, тому остаточне джерело меж — готові масиви в пакеті (M1).
- Час: локальний Whisper з мітками слів (є skill `audiobook-to-epub`; конвертер уже дає `transcript.vtt`) → вирівнювання з реченнями книжки → `null` за низької впевненості.
- Переклад: пакетний переклад через API (платно, лише з дозволом) або експорт кешу з застосунку.
- Хмарне вирівнювання й передавання книжки або аудіо стороннім сервісам — не дозволено цим документом.

## Критерії приймання (D0–D1)

1. Синтетичний пакет імпортується як одна книжка з оригіналом, перекладом, аудіо й часом.
2. Невалідний пакет відхиляється з зрозумілим повідомленням, бібліотека не змінюється.
3. Час не застосовується до іншої редакції тексту або заміненого аудіо.
4. Перевірено відтворення, паузу, перемотування, зміну швидкості, перехід доріжки, повторне відкриття, речення без відповідності.
5. Переклад доступний без запиту до ШІ; офлайн відтворюється локальне аудіо.
6. Точність виміряна на контрольних реченнях; допуск погоджується після D0; точність до слова не вимагається.
7. Перевірено великий пакет і перерваний імпорт на iPad Safari; ліміт 50 МБ текстів не переноситься на аудіо.
8. Старі книжки EPUB/TXT/MD і окремо додане аудіо працюють, як раніше.

**Вимірювання (2026-11-10, користувач, Safari на Mac, production-збірка гілки через `vite preview`)**

Результат: на контрольних реченнях підсвічування змінюється **вчасно**, разом з голосом диктора. Точнішої числової оцінки не робилося. Порядок вимірювання:

1. `npx vite build --outDir build/preview-d0 && npx vite preview --outDir build/preview-d0 --port 5181` і відкрити адресу в Safari. `npm run dev` не годиться: CSP у `index.html` блокує стилі, які Vite вставляє в режимі розробки. ### D2c (2026-11-11) — інструмент Reader для окремого конвертера, гілка `d2c-reader-tool`

Погоджено 2026-11-11 («ok D2c»). Конвертер (`converter-pwa-youtube`, гілка `d2c-reader-book`) готує книжку в інтерфейсі на Mac, а все про текст робить цей репозиторій через версійований інструмент; репозиторії не об'єднуються, алгоритми не копіюються.

- `scripts/reader-tool.ts` → `npm run reader-tool` (`scripts/build-reader-tool.mjs`) збирає обидві мови в окрему тимчасову теку, публікує її як незмінну `build/reader-tool/versions/<id>/` і лише тоді одним перейменуванням замінює `build/reader-tool/manifest.json` (протокол `TOOL_PROTOCOL` = 1, коміт, SHA-256 і шлях кожного файла): читач маніфесту бачить або весь старий пакет, або весь новий, також за двох збірок одночасно. Команди: `version`, `chapters` (розділи з першим реченням), `template` (лише розділи доріжок, без аудіо), `build` (`scripts/reader-book.ts`), `validate` (`validatePackage` і, з `--audio-dir`, розмір і SHA-256 аудіо поруч). Відповідь — один JSON-рядок; помилка входу — `ok: false, kind: input`, код 1.
- Конвертер запускає інструмент лише після звірки протоколу й SHA-256 із закріпленими у своєму `reader_tool.lock.json`; інший файл відхиляється до свідомого `converter readerbook pin-tool`.
- Конвертер виконує саме перевірені байти: Node читає їх зі stdin (`node --input-type=module -`), а не за шляхом, який можна підмінити після перевірки; відповіддю вважається лише вихід 0 з JSON-об'єктом і `ok: true`.
- `validate` на JSON, що не є пакетом (`null`, `[]`, `tracks: [null]`), відповідає `valid: false`, а не аварією.
- Тести: `tests/unit/reader-tool.test.ts` (6 на мову: збирає інструмент і запускає його як конвертер; повторна збірка не змінює маніфест і не лишає тимчасових тек).
