# Один файл підготовленої книжки для iPad: ідея та оцінювання

**Стан:** записано 2026-11-11, без реалізації. Пов'язано: `specs/013-prepared-book/` (формат `.reader.json`, D0–D2c), Конвертер `converter-pwa-youtube/specs/004-mp3-reader-book/` (MP3 без тексту, автоматичний переклад, YouTube). YouTube у самому Reader лишається відхиленим (`specs/004-youtube-audio/idea.md`): усе, що стосується YouTube, — у Конвертері.

| | |
|---|---|
| **Проблема** | Готова книжка — це `.reader.json` і кілька MP3. На iPad у «Файлах» їх треба вибрати разом; легко пропустити доріжку, незручно передавати через AirDrop/iCloud. Конвертер для MP3 без тексту потребує від інструмента Reader нової команди (речення з часом за готовими мітками слів). |
| **Для кого** | Читач English Reader / Polish Reader на iPad; Конвертер як виробник пакетів. |
| **Бажана зміна** | Один файл-контейнер із пакетом і MP3, який Reader імпортує безпечно частинами; тека `.reader.json` + MP3 і далі підтримується. Інструмент Reader (протокол 2) уміє збирати речення з часом за мітками слів і перевіряти контейнер. |

Вимога користувача 2026-11-11 (дослівно): «А далі, буде два файли, чи будемо робити zip, щоб хранився один файл?»

Рішення користувача 2026-11-11 (дослівно): «а можна .polenuk? Я думаю, що згодом перейдемо до назви polenuk-reader». Бажане розширення контейнера — `.polenuk`, один для обох мов; можливий майбутній бренд polenuk-reader — зараз нічого не перейменовується. Працездатність на iPad не перевірено.

**Що є (перевірено кодом):** імпорт `.reader.json` + MP3 (`src/core/prepared/import.ts`): перевірка пакета, доріжок за назвою/розміром/SHA-256, місця; книжка додається останньою, після збою записане прибирається, сироти прибираються під час запуску. ZIP-читач (`src/core/import/zip.ts`) — для EPUB: stored і deflated, без ZIP64, тримає архів у пам'яті, стеля розпакованого 200 МБ. Повторний імпорт пакета створює другу книжку. Інструмент `reader-book` протоколу 1 (D2c). Прогалини, знайдені перевіркою dot 2026-11-11: прибирання сиріт під час запуску (`App.tsx`) не координується з імпортом в іншій вкладці; запасне збереження аудіо (`store.ts` `putFile`) читає всю доріжку в пам'ять; адаптер Конвертера приймає лише протокол 1 — усе це враховано в `spec.md` і `plan.md`.

**Оцінювання.** Користь — один файл на iPad і основа для MP3-сценарію Конвертера. Витрати — читач ZIP частинами, перевірки безпеки, реальна перевірка «Файлів»/Safari, нова команда інструмента. Ризики — розширення може бути недоступне у виборі файлів iPad; пам'ять і місце при великих файлах; відхилення від нативного еталона (записати V-нн). Альтернатива — лише тека (уже є). **Рекомендація: Продовжити**, починаючи з реальної перевірки iPad до реалізації імпорту.
